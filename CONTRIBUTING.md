# Contributing to DJ-OS 🌀

First off, thanks for taking a look at the code. **DJ-OS** isn't just a repo; it's a high-performance 3D operative environment. We build at ludicrous speed, and we value "vibe" as much as "logic."

## 🛡️ The Philosophy
1. **Ship beats perfect.** If it works and the visual is clean, push it.
2. **AI-Native Development.** We treat agents like partners. If you used Claude or GPT to solve a complex Three.js shader, tell us—we want to know the prompt.
3. **High Fidelity.** If a component drops below 60fps, it needs optimization.

## 🚀 How to Jump In

### 1. The Setup
Since this is a Next.js + Three.js + Web Audio API stack, ensure your local environment is primed:
```bash
git clone [https://github.com/Sm0k367/dj-os.git](https://github.com/Sm0k367/dj-os.git)
cd dj-os
npm install
npm run dev
2. What We Need Right Now
We are currently focusing on the Hyper-Void navigation layer. Check the issues for:

🔊 Audio-Reactive Shaders: Improving the way GLSL reacts to sub-bass frequencies.

🧊 Instanced Mesh Optimization: Pushing the particle count from 15k to 50k+.

🤖 MCP Integration: Making the OS controllable via Model Context Protocol.

🛠️ Pull Request Process
Branch naming: Keep it short (e.g., feat/neon-glow or fix/audio-latency).

The "Vibe Check": Include a screen recording or a screenshot of your changes in the PR description. If it’s a visual change, we need to see it.

Draft PRs: Feel free to open a Draft PR early if you want feedback on a specific generative-art approach.

🎰 AI Agent Workflow
If you are using an agent to contribute:

We recommend Claude 3.7 or Cursor.

Please ensure the agent doesn't strip out the custom Three.js logic during refactors.
